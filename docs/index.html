ZipRepairTool.

Normal ZIP repair for archives damaged in transit — plus a full integrity check, so any extractor can open them again.

⬇ Download JAR (v1.0) GitHub Repository

01Why some archives fail

Archives damaged in transit have inconsistent metadata: their central directory and local file header metadata disagree (rewritten names, altered sizes/CRC-32, fake directory entries, forged EOCD signatures). Strict extractors — 7-Zip, WinRAR, Windows Explorer, Python’s zipfile — reject them, while JVM applications still read them because java.util.zip.ZipFile trusts the central directory. Some damaged archives also have corrupt file contents (PNG chunk CRC-32 / IDAT Adler-32, Ogg header fields, minified JSON).

02Features

  • Check — full inspection: entry count, local/central metadata divergence (names, sizes, CRC), fake directories, forged EOCD, data CRC-32 verification, unreadable entries — with an OK / DAMAGED verdict.
  • Repair — rebuild a clean ZIP via ZipFile + ZipOutputStream; the output opens in any extractor. It also repairs damaged PNG / Ogg / JSON contents so extracted files open again.

03Usage

java -jar ZipRepairTool.jar                              # GUI (Check / Repair)
java -jar ZipRepairTool.jar -check <in.zip>
java -jar ZipRepairTool.jar -repair <in.zip> <out.zip>

UI language follows the system locale (Chinese / English); CLI output is English. Requires JDK 8+.
