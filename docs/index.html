mcpack-deobfuscator.

Deobfuscate Minecraft resource packs (mcpack) protected or obfuscated by PackSquash tools — plus a full integrity check and a tunable obfuscate mode.

⬇ Download JAR (v1.2.1) GitHub Repository

01Why protected packs fail

Protected resource packs are usually not encrypted at all: their central directory and local file header metadata disagree (rewritten names, altered sizes/CRC-32, fake directory entries, forged EOCD signatures). Strict extractors — 7-Zip, WinRAR, Windows Explorer, Python’s zipfile — reject them, while Minecraft still reads them because java.util.zip.ZipFile trusts the central directory. Some obfuscators additionally corrupt the file contents (PNG chunk CRC-32 / IDAT Adler-32, Ogg header fields, minified JSON), so the extracted files fail to open even after the container is rebuilt.

02Features

  • Check — full inspection: entry count, local/central metadata divergence (names, sizes, CRC), fake directories, forged EOCD, data CRC-32 verification, unreadable entries — with an OK / PROTECTED / DAMAGED verdict, plus PackSquash detection (obfuscated PNG, Ogg, JSON).
  • Deobfuscate — rebuild a clean ZIP via ZipFile + ZipOutputStream; the output opens in any extractor. It also deobfuscates PackSquash-obfuscated PNG / Ogg / JSON contents so extracted files really display and play.
  • Obfuscate — the inverse of deobfuscation, with tunable parameters: name rewrite mode, percentage, fake directories, whitelist, forged EOCD, CRC perturbation, RNG seed, and content obfuscation of PNG / Ogg / JSON.

03Usage

java -jar mcpack-deobfuscator.jar                              # GUI (Check / Deobfuscate / Obfuscate)
java -jar mcpack-deobfuscator.jar -check <in.zip>
java -jar mcpack-deobfuscator.jar -deobfuscate <in.zip> <out.zip>
java -jar mcpack-deobfuscator.jar -obfuscate <in.zip> <out.zip> \
      [--name <none|upper|digit|random>] [--percent <0-100>] \
      [--fake-dir <0-100>] [--eocd] [--crc] [--no-sizes] \
      [--content] [--seed <n>] [--whitelist <a,b,c>]

UI language follows the system locale (Chinese / English); CLI output is English. Requires JDK 8+.
